# dcr 0.4.2「交接线保命补丁」实施规划

> 基线：0.4.1（`435601b`）｜范围定稿：`dcr-0.4.2-范围定稿-2026-10-25.md`｜本文只规划，不含实现结论。
> 一句话目标：**保证「dcr 叫你交接」永远早于「DSH 自己压历史」；做不到就明确告警，不静默失效。**

## 0. 规则口径（实现前先钉死）

| 项 | 口径 | 落点 |
|---|---|---|
| 硬上限 | `cap = floor((参考线 − 5pp) × 100) / 100`，整数百分位；deepseek-flash（实际 67.8%）→ **62%** | `core/handoff-guard.js` |
| 参考线 | 优先 `state.native.ratio`（实际触发线）；算不出 / 原生关闭时见下 | 同上 |
| 超限 | **拒绝保存 + 提示目标值**，不静默夹紧 | `actions/settings.js`、`client/50-settings.js` |
| 服务端参数 | `save(patch, { nativeRatio })`：带了按实际线 −5pp；没带退回配置阈值 −1pp（0.4.1 行为） | `actions/settings.js` + `adapters/http.js` |
| 实际线 unavailable | 新规则**不告警、不阻断**；保存退回配置阈值防呆（0.4.1 行为） | guard `fallback` 语义 |
| 原生自动压缩关闭 | 不判定（DSH 不会自己压，没有截止线）；交接线可设到 99% | guard `autoEnabled=false` |
| 重算 | 目标 = cap；`cap ≤ 压缩线` 时拒绝并提示先降压缩线 | guard `compactConflict` |
| 三处告警 | 指示灯悬停卡 + 环上交接刻度警示 / `/handoff` 菜单 / 设置页常驻 | client 三个片段 |
| 一次性 toast | 仅在**观察到路由模型变化后**首次发现违规时弹一次；同路由不重复 | `client/30-indicator.js` |

浮点安全：`Math.floor((ref − margin) * 100 + 1e-9) / 100`，避免 `0.62−0.05` 这类二进制误差把 57 变成 56。

## 2. 共享纯函数：`lib/core/handoff-guard.js`

零依赖、无 IO，服务端 `import`，客户端由 `build-client.mjs` 内联（`/* @inline core/handoff-guard.js */`）。

```js
export const HANDOFF_MARGIN_PP = 5;      // 交接线相对实际触发线至少留 5pp
export const FALLBACK_MARGIN_PP = 1;     // 实际线不可用时的配置阈值防呆余量（0.4.1 口径）
export const HANDOFF_LIMIT_DEFAULT = 0.95; // cap 绝对上限（防止算出无意义的 96%+）

/**
 * @param {object} input
 * @param {number|null} input.actualRatio      当前模型实际触发线（state.native.ratio），算不出 null
 * @param {number|null} [input.configuredRatio] 配置阈值（native.thresholdRatio），兜底用
 * @param {number|null} input.handoffRatio     当前交接提醒线
 * @param {number|null} [input.compactRatio]   压缩提醒线（重算冲突判定）
 * @param {boolean} [input.autoEnabled]        DSH 原生自动压缩是否开启（false → 不判定）
 * @param {number} [input.limit]               cap 绝对上限，默认 0.95
 * @param {'actual'|'configured'|'none'} [input.fallback]
 *        actual = 只用实际线（UI 口径：算不出就不判定、不告警）
 *        configured = 实际线算不出时按配置阈值 −1pp 防呆（服务端保存口径，0.4.1 兼容）
 * @returns {{
 *   source:'actual'|'configured'|null,   // 本次判定用的参考线
 *   actualRatio:number|null, actualPercent:number|null,
 *   configuredRatio:number|null, configuredPercent:number|null,
 *   handoffRatio:number|null, handoffPercent:number|null,
 *   compactRatio:number|null, compactPercent:number|null,
 *   cap:number|null, capPercent:number|null,  // 硬上限（比例 / 整数百分位）
 *   ok:boolean,                               // 无参考线时 true（不阻断）
 *   severity:'ok'|'warn'|'late'|'unknown',
 *   reason:'ok'|'late'|'margin'|'fallback'|'no-reference'|'invalid-handoff'|'no-cap',
 *   message:string,                           // 中文一句；ok/unknown 为 ''
 *   target:number|null,                       // 「按实际线重算」目标（仅 source=actual）
 *   compactConflict:boolean,                  // target ≤ 压缩线 → 重算会违反现有约束
 * }}
 */
export function handoffGuard({ … } = {}) { … }

/** 只算上限（比例/整数百分位），供输入框 max 与文案复用；无法计算返回 null。 */
export function handoffCapOf(referenceRatio, { marginPp = HANDOFF_MARGIN_PP, limit = HANDOFF_LIMIT_DEFAULT } = {}) { … }
```

判定顺序：

1. `autoEnabled === false` → `source=null, ok=true, severity='unknown', cap=null, target=null`（不判定）。
2. 有效 `actualRatio`（`0<r<1`）→ `source='actual'`，`cap=handoffCapOf(actualRatio)`（−5pp、floor 到百分位、≤limit）。
   - `handoffRatio` 非有效数字 → `unknown`（不阻断）。
   - `handoff > actual` → `late`；`handoff > cap` → `warn`；否则 `ok`。
3. 实际线不可用且 `fallback='configured'` 且配置阈值有效 → `source='configured'`，`cap = configured − 1pp`（floor）。
   - `handoff > cap` → `severity='warn'`（文案沿用 0.4.1 的「必须低于原生压缩线」口径）。
4. 其余 → `source=null, unknown, 不阻断`。
5. `compactConflict = cap !== null && compactRatio !== null && cap ≤ compactRatio + 1e-9`；命中时 `message` 追加
   `按实际线重算目标 X% 不高于压缩线 Y%，请先把压缩线降到 X% 以下。`

### 文案（简洁、带目标值）

- late：`交接线已晚：当前模型实际触发 67.8%，交接线 70% 会在原生压缩之后（DSH 会先压历史）；最高可设 62%。`
- warn（actual）：`交接线偏晚：当前模型实际触发 67.8%，交接线 65% 距原生压缩不足 5 个百分点；最高可设 62%。`
- warn（configured 兜底）：`「交接提醒线」必须低于 DSH 原生自动压缩线（配置阈值 80%），否则原生压缩会先动手；最高只能设到 79%。想设更高请先在设置里关闭「DSH 原生自动压缩」。`
- 百分比显示：`67.8`（一位小数、整数不带 `.0`），cap 一律整数。

## 5. 测试计划

1. **单测**：`node test/handoff-guard.mjs`（上表 1–20）；`npm test` 全量跑既有 16 个测试。
2. **HTTP 集成**：`test/plugin-load.mjs` H1–H4（真实 HTTP 路由 + 真实 `save()` + 临时设置文件/临时 profile，不碰 `~/.dsh`）。
3. **构建一致性**：`node scripts/build-client.mjs` 后 `node scripts/build-client.mjs --check` 必须 0；`git status` 只含预期文件。
4. **行为验证（临时设置文件）**：
   - 带 `nativeRatio=0.678` 保存 0.65 → 拒绝，`field` + 「最高 62%」；
   - 保存 0.62 → 通过；保存 0.63 → 拒绝；
   - 不带 `nativeRatio` 保存 0.65 → 通过（兼容）；
   - `nativeRatio` 非法/缺省 + 0.85 → 拒绝（兜底 79%）；
   - `autoEnabled=false` → 0.9 通过（不判定）。
5. **真实宿主（只读）**：`GET /api/compact-relay-settings` + `/api/compact-relay-state`（本机 60592，带浏览器 cookie 则读；没有 cookie 就记录 401/403 并说明）。**不对运行中的 0.4.1 宿主 POST**，避免写入用户真实设置。
6. **需小潇真机确认**（本环境无 Chrome/CDP，不伪造）：设置页 max=62 与提示、环上警示、`/handoff` 菜单 ⚠、换模型后一次性 toast、截图存档。

## 6. 风险与回滚

| 风险 | 影响 | 处理 |
|---|---|---|
| 服务端兜底上限从「< 配置阈值」收紧为「≤ 配置阈值 −1pp」 | 手改文件里 79.5% 这类亚百分点值会被拒（0.4.1 放行） | 与 0.4.1 提示文案一致（本来就写「最高 79%」）；UI 只出整数百分比；CHANGELOG 注明 |
| 已存的高交接线（如 0.4.1 存的 65%）升级后保存任何设置都被拒 | 用户必须先改交接线 | 设置页常驻告警 + 一键重算；错误文案给出目标值与操作指引 |
| 客户端 `nativeRatio` 可能过期（设置页打开后换了模型） | 服务端按过期线校验 | 设置页加载即拉 state；错误文案带目标值可自查；指示灯实时告警兜底 |
| 真实线 unavailable 时 UI 输入上限仍按配置阈值（79%） | 与「不阻断」字面有张力 | 仅限制输入框上限、不出告警；服务端兜底规则本来就是 0.4.1 行为 |
| 环上警示改变 SVG 节点 | 可能影响 `native-line.mjs` 的 bundle 字符串断言 | 只加节点不改分段；测试断言基于源码字符串，按需同步 |
| 构建产物与源码不一致 | `npm test` 的 `--check` 直接失败 | 改完必跑 build + check |

**回滚**：`git switch main`（分支未合并，主线零影响）或 `git revert <commit>`；npm 未发布，无外部影响。
